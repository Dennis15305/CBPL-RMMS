CBPL RAW MATERIAL METERING SYSTEM
Целевая версия для EcoStruxure Machine Expert 2.3 и TM241CEC24T


1. НАЗНАЧЕНИЕ СИСТЕМЫ
====================

Система обрабатывает шесть одинаковых однофазных энкодеров:

- каналы 1...5 считают текущий и предыдущий рулон пяти раскатов;
- канал 6 считает общий метраж и скорость линии;
- каждый энкодер имеет 250 импульсов на оборот;
- окружность каждого мерного колеса равна 250 мм;
- один импульс соответствует одному миллиметру перемещения;
- движение учитывается только в одном направлении по сигналу A+.

Все пять раскатов обрабатываются постоянно. Отдельной маски разрешённых каналов
нет: неподвижный или неподключённый энкодер просто не формирует приращение, а
остальные раскаты продолжают работать независимо.

Для каждого раската предусмотрены две кнопки:

- SPLICE всегда завершает текущий рулон;
- RESET при длине 100 м и более завершает текущий рулон;
- RESET при длине менее 100 м очищает только текущий рулон;
- короткий RESET не изменяет предыдущий рулон и номер последовательности.

Пять панелей DWIN подключаются к одному RS-485:

- ПЛК является Modbus RTU master;
- панели являются Modbus RTU slave;
- адреса панелей: 1, 2, 3, 4, 5;
- каждая панель показывает только свой раскат;
- постоянный физический номер панели/раската: 1...5.

Смена определяется по часам ПЛК:

- смена 1: 08:00...19:59:59;
- смена 2: 20:00...07:59:59;
- смена не сбрасывает текущие/предыдущие рулоны и общий метраж линии;
- при смене номера отдельно обнуляются только сменные накопители выпуска и сырья.

Рабочие счётчики и очередь имеют разное поведение при отключении:

- после перезапуска ПЛК текущие и предыдущие значения рулонов сохраняются;
- общий метраж линии также начинается с нуля;
- очередь событий, состояния рулонов, сменные накопители и настройки Стопмашины
  хранятся как PERSISTENT RETAIN;
- событие удаляется из очереди исключительно после подтверждения его EventId.


2. СОСТАВ ФАЙЛОВ
================

DUT:

E_RollEndReason.txt
    Причина завершения учтённого рулона.

E_ChannelStatus.txt
    Состояние канала HSC и его диагностика.

ST_HscState.txt
    Абсолютный отсчёт, приращение импульсов и состояние одного HSC.

ST_RollState.txt
    Текущий рулон, предыдущий рулон и отброшенный короткий метраж.

ST_LineState.txt
    Общий метраж и скорость шестого энкодера.

ST_ShiftState.txt
    Номер смены, местное время и состояние RTC.

ST_SystemDiagnostics.txt
    Общая диагностика проекта.

ST_RollEvent.txt
    Неизменяемый снимок одного завершённого рулона для очереди и базы данных.

ST_StopMachinePersistent.txt
    Сохраняемые заказ, базовые метражи и настройки Стопмашины ЛГК.

ST_StopMachineState.txt
    Рабочее состояние, выпуск, таймеры и последняя причина обрыва ЛГК.


GVL:

GVL_Constants.txt
    Все постоянные параметры и границы системы.

GVL_IO.txt
    Только аппаратные показания HSC и физические кнопки.

GVL_Runtime.txt
    Рабочие состояния пяти раскатов, линии и смены.

GVL_HMI.txt
    Пять независимых пакетов Modbus для пяти DWIN.

GVL_Diagnostics.txt
    Общая структура диагностики.

GVL_SCADA.txt
    Очередь рулонов %MW2000...%MW2022 и атомарный пакет заказа ЛГК
    %MW2030...%MW2042 для службы-сборщика/WinCC по Modbus TCP.

GVL_HAIWELL.txt
    Read-only карта %MW2100...%MW2229 для центральной Haiwell A10-W.

GVL_StopMachine.txt
    Изолированная карта %MW2300...%MW2399 для HMI Стопмашины ЛГК.


Persistent Variables:

PersistentVars.txt
    Постоянная FIFO-очередь 128 событий, состояния раскатов, сменные накопители,
    настройки Стопмашины и версия разметки постоянной памяти.


Функциональные блоки:

FB_InputFilter.txt
    Подтверждает непрерывное нажатие кнопки в течение 50 мс.

FB_HscTracker.txt
    Вычисляет новые импульсы по абсолютному HSC, обрабатывает переход через
    ноль и отбрасывает невозможные скачки.

FB_RollCounter.txt
    Один экземпляр обслуживает один раскат. В SR_Main создаётся пять экземпляров.

FB_LineMeter.txt
    Обрабатывает шестой энкодер, считает общий метраж и скорость, м/мин.

FB_ShiftManager.txt
    Читает RTC и выбирает номер смены. На рулоны не воздействует.

FB_DwinDataPacker.txt
    Переводит длину из миллиметров в десятые доли метра и делит UDINT
    на старшее и младшее Modbus-слово.

FB_RollEventQueue.txt
    Назначает EventId, хранит события по порядку и удаляет их после ACK сервера.

FB_EventPacker.txt
    Упаковывает первое событие очереди в 12 слов и рассчитывает CRC16.

FB_StopMachine.txt
    Обслуживает только ЛГК: состояния, заказ, сменный выпуск, переналадку и команды HMI.


Функция неявной проверки:

CheckBounds.txt
    Проверяет индексы массивов и устраняет предупреждение компилятора.


Программа:

SR_Main.txt
    Вызывает шесть аппаратных HSC и связывает все функциональные блоки.
    SR_Main должен вызываться только циклической задачей MAST.


Контроль протокола:

PROTOCOL_V2_TEST_VECTOR.txt
    Известное событие, ожидаемые 12 регистров и CRC16 для проверки ПЛК и Windows-службы.


3. ПОРЯДОК СОЗДАНИЯ ОБЪЕКТОВ В MACHINE EXPERT
==============================================

Перед изменениями сохранить резервную копию проекта.

Создавать объекты в следующем порядке:

1. DUT:
   E_RollEndReason
   E_ChannelStatus
   ST_HscState
   ST_RollState
   ST_LineState
   ST_ShiftState
   ST_SystemDiagnostics
   ST_RollEvent
   ST_StopMachinePersistent
   ST_StopMachineState

2. GVL:
   GVL_Constants
   GVL_IO
   GVL_Runtime
   GVL_HMI
   GVL_Diagnostics
   GVL_SCADA
    GVL_StopMachine

3. Persistent Variable List:
   PersistentVars

4. POU типа Function Block, язык ST:
   FB_InputFilter
   FB_HscTracker
   FB_RollCounter
   FB_LineMeter
   FB_ShiftManager
   FB_DwinDataPacker
   FB_RollEventQueue
   FB_EventPacker
   FB_StopMachine

5. POU типа Program, язык ST:
   SR_Main

6. POU for implicit checks:
   CheckBounds / Bound Checks


Для DUT:

- Application -> Add Object -> DUT;
- имя объекта должно точно совпадать с именем файла;
- заменить всё содержимое редактора текстом из соответствующего TXT.


Для GVL:

- Application -> Add Object -> Global Variable List;
- имя GVL должно точно совпадать с именем файла;
- вставить полный блок VAR_GLOBAL ... END_VAR.


Для PersistentVars:

- Application -> Add Object -> Persistent Variables;
- имя объекта должно быть PersistentVars;
- вставить полный блок VAR_GLOBAL PERSISTENT RETAIN ... END_VAR.


Для FB и SR_Main:

- часть между заголовками DECLARATION и IMPLEMENTATION вставляется в
  соответствующую область редактора;
- строки-заголовки с символами ===== вставлять не требуется;
- объявления всех переменных уже содержат комментарии справа.


CheckBounds рекомендуется создавать штатной командой:

- выделить Application;
- Add Object -> POU for implicit checks;
- включить Bound Checks / CheckBounds;
- не изменять автоматически созданную область Declaration.

Файл CheckBounds.txt приложен как резервный вариант, если отдельного пункта
POU for implicit checks в интерфейсе Machine Expert нет.


Старые объекты перед окончательной сборкой:

- удалить устаревший E_RollResetReason;
- полностью заменить старые ST_RollState, GVL и FB_RollCounter;
- полностью заменить SR_Main.


4. БИБЛИОТЕКИ
=============

В Library Manager должны быть доступны:

- Standard: используется TON;
- M241 PLCSystem: используется SEC.GetRtc для чтения RTC контроллера;
- библиотека M241 HSC подключается конфигурацией аппаратных счётчиков.

В текущем проекте библиотека M241 PLCSystem уже добавлена автоматически
с пространством имён SEC. Дополнительно подключать SysTimeRtc не требуется.

В GVL_Constants задано смещение Брянска UTC+3:

    c_udiLocalUtcOffsetSeconds := 10800

RTC ПЛК должен содержать правильное UTC-время. Номер смены и текущее местное
время проверяются онлайн в GVL_Runtime.stShiftState.


5. НАСТРОЙКА ЗАДАЧИ MAST
========================

Task Configuration -> MAST:

- Type: Cyclic;
- Interval: 20 ms;
- Priority: 15;
- Watchdog: Enabled;
- Watchdog time: 100 ms;
- вызываемая программа: SR_Main.

Аппаратные HSCSimple должны вызываться только из MAST.


6. НАСТРОЙКА ШЕСТИ HSC
======================

Создать HscSimple_0 ... HscSimple_5.

Для всех шести:

- Counting function: HSC Simple;
- Counting mode: Modulo-loop;
- входы A: I0, I1, I2, I3, I4, I5 соответственно;
- Bounce filter: 0.002 ms;
- Modulo: 1000000000.

Важно: финальная версия использует явный Modulo 1000000000, а не 0.

Причина: FB_HscTracker должен точно знать диапазон перехода счётчика через
ноль. Значения HSC будут 0...999999999, после чего счётчик перейдёт на 0.
Это соответствует константе:

    GVL_Constants.c_udiHscCounterRange := 1000000000

Если изменить Modulo в настройках HSC, обязательно изменить эту константу
на то же значение. Несовпадение приведёт к отбрасыванию перехода как скачка.


7. НАСТРОЙКА TM3DI16
====================

Модуль TM3DI16 подключён после контроллера.

I/O Mapping:

I0 -> GVL_IO.xReset[1]
I1 -> GVL_IO.xReset[2]
I2 -> GVL_IO.xReset[3]
I3 -> GVL_IO.xReset[4]
I4 -> GVL_IO.xReset[5]

I5 -> GVL_IO.xSplice[1]
I6 -> GVL_IO.xSplice[2]
I7 -> GVL_IO.xSplice[3]
I8 -> GVL_IO.xSplice[4]
I9 -> GVL_IO.xSplice[5]

COM входного модуля должен быть соединён с 0 V того же блока питания 24 V.
Кнопка подаёт +24 V на соответствующий вход. Постоянный монтаж выполнять
через нормальные клеммы, защиту и кнопки, рассчитанные на промышленную среду.


8. НАСТРОЙКА ПЯТИ DWIN ПО MODBUS RTU
====================================

SerialBus:

- Mode: RS-485;
- Baud rate: 9600;
- Data bits: 8;
- Parity: None;
- Stop bits: 1;
- Transmission: RTU.

Под SerialBus добавить Modbus_IOScanner.

Под Modbus_IOScanner добавить пять объектов Generic Modbus Slave:

- HMI_1, Slave address 1;
- HMI_2, Slave address 2;
- HMI_3, Slave address 3;
- HMI_4, Slave address 4;
- HMI_5, Slave address 5.

Для каждого устройства создать один канал:

- Name: HMI_N_Display;
- Function: Write Multiple Registers, функция 16;
- Start address: 16#2000, десятичный адрес 8192;
- Quantity: 13 registers;
- Cycle/trigger: Cyclic;
- рекомендуемый интервал: 200 ms;
- Response timeout: 1000 ms;
- Auto-restart communication: Enabled.

В Modbus Master I/O Mapping назначить тринадцать слов каждого устройства:

HMI_1 -> GVL_HMI.a_wHmi1Tx[0] ... [12]
HMI_2 -> GVL_HMI.a_wHmi2Tx[0] ... [12]
HMI_3 -> GVL_HMI.a_wHmi3Tx[0] ... [12]
HMI_4 -> GVL_HMI.a_wHmi4Tx[0] ... [12]
HMI_5 -> GVL_HMI.a_wHmi5Tx[0] ... [12]

Адреса %QW вручную не изменять: Machine Expert назначает их автоматически.

На всех DWIN используется одинаковая карта VP:

VP 2000...2001:
    текущий рулон, Unsigned Long Int, 4 bytes, Decimal digits = 1.

VP 2002...2003:
    предыдущий рулон, Unsigned Long Int, 4 bytes, Decimal digits = 1.

VP 2004:
    физический номер раската, Int/Unsigned Int, 2 bytes, Decimal digits = 0.

VP 2005:
    местный год ПЛК, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 2006:
    местный месяц ПЛК, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 2007:
    местный день месяца ПЛК, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 2008:
    местный час ПЛК, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 2009:
    местная минута ПЛК, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 200A:
    местная секунда ПЛК, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 200B:
    номер смены, Unsigned Int, 2 bytes, Decimal digits = 0.

VP 200C:
    статус RTC: 1 — время достоверно, 0 — время недостоверно.

VP 2005...200A оставлены как диагностическая копия местных даты и времени ПЛК.
Существующий объект даты/времени DWIN использует встроенные часы панели и не
читает эти VP. Для него необходимо добавить отдельный канал синхронизации RTC.

Для каждой панели HMI_N добавить второй канал записи:

- Name: HMI_N_RTC;
- Function: Write Multiple Registers, функция 16;
- Start address: 16#009C, десятичный адрес 156;
- Quantity: 4 registers;
- Cycle/trigger: Cyclic;
- интервал для первого стендового испытания: 1000 ms;
- после успешной проверки рекомендуемый интервал: 60000 ms;
- Response timeout: 1000 ms;
- Auto-restart communication: Enabled.

Привязка данных второго канала:

HMI_1 -> GVL_HMI.a_wHmi1RtcSync[0] ... [3]
HMI_2 -> GVL_HMI.a_wHmi2RtcSync[0] ... [3]
HMI_3 -> GVL_HMI.a_wHmi3RtcSync[0] ... [3]
HMI_4 -> GVL_HMI.a_wHmi4RtcSync[0] ... [3]
HMI_5 -> GVL_HMI.a_wHmi5RtcSync[0] ... [3]

Пакет для системного VP 009C имеет формат DWIN:

- [0] = 16#5AA5 — разрешение однократной установки RTC;
- [1] = YYMM — год от 2000 и месяц;
- [2] = DDHH — день и час;
- [3] = MMSS — минуты и секунды.

ПЛК передаёт местное московское время, уже рассчитанное со смещением UTC+3.
Дополнительное смещение в DWIN не задавать. При недостоверном времени ПЛК
первое слово становится нулевым, поэтому ошибочная дата в панель не записывается.
После настройки этого канала существующий объект RTC на экране DWIN менять не
нужно: панель продолжит отображать собственные часы, синхронизированные с ПЛК.

Каждой панели должен быть заранее назначен собственный Modbus slave address.

На физической линии:

- соединять A с A и B с B;
- использовать общую сигнальную опору/GND, если она предусмотрена устройствами;
- применять витую пару;
- ставить согласующие резисторы 120 Ом только на двух концах линии;
- не создавать звезду из длинных ответвлений.


9. ОЧЕРЕДЬ СОБЫТИЙ И MODBUS TCP
===============================

После SPLICE либо допустимого RESET блок FB_RollCounter выдаёт xRollCompleted.
SR_Main создаёт ST_RollEvent и передаёт его в FB_RollEventQueue. Очередь
переживает отключение питания, но рабочие значения энкодеров не восстанавливает.

Подробная карта регистров, формат 12 слов и порядок подтверждения приведены в:

    MODBUS_TCP_EVENT_PROTOCOL.txt

До создания службы-сборщика очередь проверяется через Modbus Poll. Сначала
необходимо добиться чистой сборки и проверить значения GVL_SCADA онлайн.


10. ПОСЛЕДОВАТЕЛЬНОСТЬ ПРОВЕРКИ
==============================

Проверять систему последовательно, не подключая всё сразу.

1. Выполнить F11 / Generate Code. Ошибок быть не должно.

2. Загрузить программу и запустить ПЛК.

3. Проверить HSC онлайн:

   GVL_IO.udiHscAbs[1...6]
   GVL_Runtime.a_stHscState[1...6].udiPulseDelta
   GVL_Runtime.a_stHscState[1...6].eStatus

   Каждый энкодер должен изменять только свой канал.

4. Проверить пять раскатов:

   PersistentVars.a_stRollState[1...5].uliCurrentLengthMm
   PersistentVars.a_stRollState[1...5].uliPreviousRollLengthMm

5. Проверить SPLICE отдельно для каждого канала.

6. Проверить RESET:

   - ниже 100000 мм предыдущий рулон не меняется;
   - начиная со 100000 мм текущий рулон становится предыдущим.

7. Проверить шестой энкодер:

   GVL_Runtime.stLineState.uliTotalLengthMm
   GVL_Runtime.stLineState.rSpeedMPerMin
   GVL_Runtime.stLineState.xMoving

8. Проверить смену и часы:

   GVL_Runtime.stShiftState.usiCurrentShift
   GVL_Runtime.stShiftState.uiLocalHour
   GVL_Runtime.stShiftState.xRtcValid

9. Подключать HMI по одной, начиная с адреса 1.

10. После проверки всех адресов соединить пять панелей на общей шине.

11. Завершить тестовый рулон и проверить:

   PersistentVars.uiEventQueueCount = 1
   GVL_SCADA.wEventReady = 1
   GVL_SCADA.a_wEventPacket[0] = 16#CB01
   GVL_SCADA.wQueueStatus = 1

12. До проверки Modbus TCP не записывать команду 16#A55A вручную: она удаляет
    подтверждённое событие из головы очереди.


11. ДИАГНОСТИКА
===============

Основная структура:

    GVL_Diagnostics.stSystem

Проверяемые поля:

- xAnyHscFault: ошибка хотя бы одного HSC;
- xAnyConfigFault: ошибка параметров пересчёта;
- xRtcFault: ошибка часов ПЛК;
- a_eHscStatus[1...6]: подробное состояние каждого HSC;
- a_xHmiOverflow[1...5]: значение не помещается в формат DWIN;
- uliProgramCycles: SR_Main действительно выполняется.

При CHANNEL_STATUS_COUNTER_JUMP недопустимое приращение отбрасывается.
Это защищает метраж от внезапного аппаратного сброса или неверного скачка HSC.


12. ЧТО ОСТАВЛЕНО НА БУДУЩЕЕ
============================

В текущую версию намеренно не входят:

- восстановление значений после отключения питания;
- физическое управление Стопмашиной (START/STOP пока не связано с выходами);
- служба-сборщик PLC -> SQLite -> SQL Server;
- связь с WinCC;
- отображение скорости и номера смены на DWIN;
- программная диагностика качества связи каждой HMI.

Эти функции добавляются отдельными слоями и не должны изменять базовую логику
учёта пяти раскатов.


13. ВАЖНО ПЕРЕД ВВОДОМ В РАБОТУ
===============================

- Проверить правильность окружности каждого реального мерного колеса.
- Выполнить контрольный прогон известной длины и скорректировать коэффициент.
- Проверить все кнопки и соответствие каналов 1...5.
- Проверить потерю связи с каждой HMI.
- Проверить остановку и повторный запуск ПЛК.
- Создать boot application после окончательной загрузки.
- Удалить все Force перед вводом оборудования в работу.
- Эта программа выполняет учёт и отображение, но не является системой
  функциональной безопасности и не заменяет аварийные цепи оборудования.


14. СТОПМАШИНА ЛГК
==================

Для новой HMI Стопмашины подготовлен отдельный интерфейс %MW2300...%MW2399.
В нём нет выбора линии и нет обращений к адресам линий 1...3. Подробный аудит
старого XML, карта регистров, команды и ограничения безопасности находятся в:

    Docs/02_Стопмашина_ЛГК.md

Заказ поступает не от HMI, а отдельным атомарным серверным пакетом
%MW2030...%MW2042. Будущая EB-панель показывает применённый заказ и передаёт только
действия оператора, параметры обрыва, настройки и номер пользователя.

Команды START и STOP меняют только состояние линии в отчёте. В программе нет
запросов физического пуска/останова и нет назначений Стопмашины на дискретные
выходы. `%MW2331` всегда равен нулю и публикует этот защитный инвариант для HMI.
